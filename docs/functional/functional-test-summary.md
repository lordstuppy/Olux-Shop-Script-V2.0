# Final Functional Gate: Summary

**Decision: BLOCKED - DO NOT SHIP.**

The application behaved correctly under everything this environment could throw at it:

- races forced with synchronisation barriers;
- payment callbacks duplicated, reordered, late, parallel and lost;
- gateway timeouts, 429, 503, cut-off answers and lost answers;
- database, worker, mail, gateway and PHP-FPM failures;
- 165,646 load requests up to 400 concurrent browsers, with 0 errors;
- a year-scale dataset.

The gate found 13 defects (4 High, 6 Medium, 3 Low) that the earlier rounds had missed, mostly in money and state handling under concurrency. All are fixed, with regression tests that failed before the fixes.

The decision is BLOCKED because mandatory gates need what this environment does not have:

- a real Shkeeper sandbox to reconcile against;
- an approved target workload, measured on production-like hardware;
- more than one application instance;
- the screen-reader and real-user checks the UX audit already reported.

None of these were treated as passed.

## Large data

This is gate F11. The dataset was the simulation seed plus `tests/performance/scale-data.sql`: 20,204 products, 200,000 orders with 250,000 lines, 50,565 users, 500,033 notifications, 1,002,560 audit entries and 420,000 ledger entries. One buyer was given a history of 1,500 orders and 2,000 notifications.

**41 of 41 checks passed** ([evidence/large-data.json](evidence/large-data.json)):

- **Pages:** first and last pages of the catalogue, admin orders and audit log, and the long buyer history, each under 0.3 s.
- **Bad page numbers:** past the end, 0, -1, text and a null byte all handled without an error.
- **Search:** a 100-character Unicode search.
- **Exports:** the full order export streamed 200,000 rows (28 MB) in 4 s with the app container at 69 MiB; the user export streamed 50,565 rows.
- **Reconciliation:** over 200,000 orders in 0.6 s.
- **Input limits:** the maximum is accepted and the maximum plus one is refused with a message. This covered title 160, description 20,000, price 999,999.99, quantity 10 and a 100 % coupon. A 49 MB upload (limit 50 MB) was stored in full.

## CI enforcement

| Policy | Job | When | What |
|---|---|---|---|
| Fast checks on every pull request and push | `php` | every push and PR | PHPUnit (including `FunctionalGateTest`), Pint, ASCII, dependency audit |
| Broader integration and end-to-end | `browser`, `security`, `performance` | every push and PR | Browser suite, security gate, performance gate |
| Scheduled adversarial and stress testing | `functional` | weekly (Monday 04:17 UTC) | `scripts/functional-gate.sh`: simulation phases 1-12, load profiles, large data, then `matrix.py --check` |
| Release-candidate verification | `functional` | `workflow_dispatch` on the candidate | The same, on the exact revision; the artifact keeps the reports |

- **Only against disposable stacks:** destructive stages (simulation, load, large data) run only against the stack the job starts on its own runner, never against production.
- **Who decides:** `matrix.py --check` exits 1 unless every gate passes. The decision comes from the run results; the script cannot mark a scenario passed that did not run.
- **Protecting the gate:** the gate files are listed in `.github/CODEOWNERS`. For that to protect them, the owner must turn on "Require review from Code Owners" and make `php`, `browser`, `security`, `performance` and (for releases) `functional` required checks. These are repository settings outside the code.

## To reach PASS

1. Run the payment, refund and payout scenarios against a Shkeeper sandbox and reconcile them (G-01, F5, F14).
2. Approve a target workload and SLOs, then run the load profiles on production-like hardware with a separate load generator (G-07, F10).
3. Run two app instances behind the load balancer for the live-update and race scenarios (G-06, F8).
4. Close the UX audit's screen-reader and real-user checks (G-10, F13).
5. Run `scripts/functional-gate.sh` through the CI job `functional` on the release candidate. It must report PASS.
